# Web Reel (Stitching) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the web page join several trimmed clips into one MP4 with the desktop's transitions, applying the existing cards, music, lower-third, watermark and format once to the whole reel.

**Architecture:** The single ffmpeg export graph (`exportGraph.ts`) takes a list of clips instead of one, normalises each, joins them with `concat` or an `xfade`/`acrossfade` chain, and then runs the existing music, card, watermark and loudness stages on the joined reel. The page holds an immutable reel (list of clips plus selection and music) in a pure module; components render it. One clip stays the current flow.

**Tech Stack:** TypeScript, React, Vite, ffmpeg.wasm (`@ffmpeg/core@0.12.10`), Node test runner (`npm test`, with the real core in Node via `web/src/lib/__tests__/support/ffmpegCore.ts`), Playwright (`npm run e2e`).

**Spec:** `docs/superpowers/specs/2026-10-20-web-reel-design.md` (builds on the web and branding specs).

## Global Constraints

- One clip must behave exactly as today: same filter graph strings for a one-clip plan, same output, same UI flow, existing tests unchanged in meaning.
- Desktop transition rules (`src/main/exportReel.ts`): styles `fade, dissolve, wipeleft, wiperight, slideleft, slideright, circleopen, circleclose, pixelize, zoomin, random`; duration default 0.75 s, clamped to 0.1–2 s, then `min(duration, shortestClip / 2)`; `random` rolled per join; audio uses `acrossfade` for every style; running length drops by the duration at each join.
- Transition settings default to off / fade / 0.75 s, are stored with the other settings, and each stored field is validated on its own.
- Original format: output size is the first clip's, fitted within 1920x1080 with even sides; later clips are scaled to fit and padded. Presets reframe each clip with the desktop filter.
- With two or more clips (or a card) every clip is normalised to the frame size, sar 1, yuv420p, 30 fps, timestamps from zero. A clip with no audio contributes silence of its own length.
- Music, its fades and its loop follow the whole reel's length; cards stay silent; lower-third and watermark cover everything.
- File name `<first file name>-reel-<N>-clips.mp4` for two or more clips; the single-clip name is unchanged.
- Warnings never block: phones above 6 clips, desktops above 12, plus the existing size warning applied to the combined size.
- Immutable state, files under 400 lines, no `console.log`, nothing leaves the origin, every temporary ffmpeg file is deleted after an export, cancelled or not.

## Review Focus

1. **Mixed clips in one reel:** different sizes and aspect ratios, a different frame rate, and one clip with no audio, with and without transitions (Tasks 3, 4).
2. **Short clips vs transitions:** a 0.5 s clip with a 2 s transition (duration clamps to 0.25 s), random styles per join, transitions combined with cards and music keep exact lengths (Tasks 1, 3).
3. **List edits:** removing the selected or last item, reordering with a selection, the same file twice, adding clips while earlier audio probes are still running, and starting over during an export (Tasks 5, 6, 7).
4. **Phones and memory:** many mounted files, cancel mid-run, cleanup of every temp file, the clip-count warning (Tasks 4, 6, 7).
5. **Corrupt stored transition settings** (wrong types, out-of-range numbers, unknown style) fall back per field (Task 2).
