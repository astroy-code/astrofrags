# Astrofrags Web (Trim & Export) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static GitHub Pages site where a user picks a video, sets a start and end, and exports a trimmed H.264 MP4 entirely in the browser, on desktop and phones.

**Architecture:** A new, small React app under `web/` with its own Vite config, fully separate from the Electron renderer (`src/renderer`) so the desktop build is untouched. Pure logic lives in `web/src/lib/` (unit-tested with Node's built-in runner, like `src/main/__tests__`). ffmpeg.wasm (single-threaded core, self-hosted in the build) does the export; the picked `File` is mounted read-only via WORKERFS so the whole input is never copied into WASM memory.

**Tech Stack:** TypeScript, React 18, Vite 5 (already in repo), `@ffmpeg/ffmpeg@0.12.15`, `@ffmpeg/core@0.12.10`, Node test runner, Playwright (E2E), GitHub Actions Pages.

**Spec:** `docs/superpowers/specs/2026-10-20-web-version-design.md`

## Global Constraints

- Desktop (Electron) app must build, run and release exactly as before; do not edit `src/**` or `electron.vite.config.ts`.
- No network call carries user video; ffmpeg core files are self-hosted with the site, no third-party CDN at runtime.
- Single-threaded ffmpeg.wasm core only (no `SharedArrayBuffer`, no COOP/COEP, no service-worker workaround) unless measurement later justifies it.
- Site is served under the repo subpath (`/astrofrags/`): all asset URLs are base-relative (`base: './'`).
- Export: libx264, `ultrafast`, crf 23, `yuv420p`, AAC, `+faststart`, frame-accurate (re-encode). No stream-copy option.
- Audio: export keeps the file's first audio stream (same one `<video>` plays); no mixing, no track picker. Multi-track files show a one-line notice that the desktop app can choose.
- Over-limit files are a warning on every device, never a hard block; phones get stronger wording and "Try anyway". Starting soft limit ~500 MB desktop; phone value is lower (plan picks 200 MB, tune on a real phone).
- Undecodable video (zero video dimensions or media error after metadata) shows a plain message pointing to the desktop app; no HEVC decoder or preview transcode in this version.
- Single stacked column layout that works on a phone.
- Repo conventions: TypeScript, immutable updates (never mutate arguments), small files (<800 lines), no `console.log`, pure logic tested with `node --test`. Commit format `<type>: <description>` ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Non-goals (do not build): peaks, OCR, captions, reels, branding, presets, audio-track picker, Medal integration, accounts/backend/analytics, PWA.

## Review Focus

Input classes the spec implies but no explicit requirement tests; each is pinned by a test in the task named.

1. File with **no audio stream** must still export (Task 4: `0:a:0?` mapping asserted).
2. Medal-style **file names with spaces, en dashes, emoji** must yield a safe output name (Task 4).
3. **Duration `NaN`/`Infinity`/0** (some phone files before metadata loads) must not enable export or produce NaN times (Task 2).
4. **Undecodable codec** (HEVC where the browser can't decode): `videoWidth === 0` must produce the message, not a black player with a live Export button (Task 5).
5. **iPad reporting a Mac user agent** must be treated as a phone for the stricter size warning (Task 3).

### Task 6: ffmpeg.wasm runtime (probe, export, deliver)

**Files:**
- Create: `web/src/lib/ffmpegInstance.ts`, `web/src/lib/exportClip.ts`, `web/src/lib/deliverClip.ts`

**Interfaces:**
- Consumes: `buildTrimArgs`, `countAudioStreams`, `trimmedFileName` (Task 4), `validateTrimRange` (Task 2).
- Produces:
  - `getFFmpeg(): Promise<FFmpeg>`: lazy singleton; loads core from `new URL('ffmpeg/ffmpeg-core.js', document.baseURI)` and the `.wasm` beside it; concurrent callers share one load.
  - `resetFFmpeg(): void`: terminates and clears the singleton so the next `getFFmpeg()` reloads (used by cancel).
  - `probeAudioStreams(file: File): Promise<number>`: mounts the file, runs `-i`, parses the log with `countAudioStreams`; resolves `0` on any failure (best-effort, never throws).
  - `exportTrimmedClip(req: { file: File; start: number; end: number; duration: number; onProgress: (ratio: number) => void; signal?: AbortSignal }): Promise<{ blob: Blob; fileName: string }>`: rejects with `Error` for an invalid range (via `validateTrimRange`), an aborted signal (after `resetFFmpeg()`), ffmpeg failure, or an empty output.
  - `deliverClip(blob: Blob, fileName: string, platform: Platform): Promise<'shared' | 'downloaded'>`: on mobile uses `navigator.canShare({files})` + `navigator.share`, otherwise (and on share failure other than user cancel) downloads via an object-URL anchor; revokes the URL afterwards.

- [ ] **Step 1: Implement `ffmpegInstance.ts`** per the interface.
- [ ] **Step 2: Implement `exportClip.ts`.** Wrap the pick in `new File([file], 'input', { type: file.type })` (no data copy; sanitizes the name), `createDir('/in')`, `mount('WORKERFS', { files: [wrapped] }, '/in')`, run `buildTrimArgs`, wire `ffmpeg.on('progress')` to `onProgress` (clamped 0..1), read the output, and `unmount` + `deleteFile` in `finally` so repeated exports don't accumulate memory.
- [ ] **Step 3: Implement `deliverClip.ts`.**
- [ ] **Step 4: Verify.** `npm run typecheck` exits 0. Behavior is covered by Task 8 (E2E); no unit test because these wrap browser/WASM APIs.

- `App` holds one session object replaced immutably on each change: `{ file, objectUrl, duration, range, platform, audioStreams, previewBroken, exportState }`; revoke the old object URL when a new file is picked.
- On pick: compute `detectPlatform(navigator.userAgent, navigator.maxTouchPoints)`; if `checkFileSize` is `'warn'` show a warn Notice (phones: stronger wording plus a "Try anyway" button that dismisses the warning; desktop: informational, no gate); call `probeAudioStreams` in the background and, if the count is above 1, show the one-line notice that the web version uses the default audio track and the desktop app can choose.

- `ExportBar`: export button enabled only when `validateTrimRange` is ok and the preview isn't broken; shows progress percent; Cancel aborts via `AbortController` and the session returns to the ready state; on success calls `deliverClip` and shows the delivered file name and a "Trim another" action; failures show an error Notice with the message from the rejected `Error`.
